# SQL 작성 규칙

## 파일과 호출 방식

- 분석 노트북 하나당 `sql/NN_*.sql` 하나를 기본으로 한다.
- 여러 쿼리는 `-- name: 쿼리명 | 목적` 마커로 구분한다.
- 노트북은 공통 `load_queries()`와 `run()` 또는 기존 프로젝트에서 검증된 동등한 방식으로 쿼리를 이름 호출한다.
- 같은 지표 정의를 여러 SQL 파일에 복사하지 않는다. 공통 정의가 필요하면 단일 뷰·CTE·문서에서 관리한다.

## 역할 분담

- SQL: 필터, 조인, 원시 집계, CASE WHEN 분류, 윈도우 계산
- Python: 통계 검정, 피벗, 시각화, 표시용 반올림, SQL 미지원 연산
- SQL은 가능한 한 원시 `COUNT`, `SUM`, `AVG`까지 반환하고 표현용 포맷은 Python에서 처리한다.

## 스타일

- SQL 키워드는 대문자로 작성한다.
- 들여쓰기는 공백 4칸을 사용하고 탭은 사용하지 않는다.
- 컬럼을 한 줄에 과도하게 나열하지 않는다.
- 복잡한 로직은 의미 있는 이름의 CTE로 나눈다.
- `SELECT *`는 탐색 단계 외에는 피하고 필요한 컬럼을 명시한다.
- 예약어를 컬럼 별칭으로 사용하지 않는다.
- 매직 넘버와 제외 조건에는 이유를 주석으로 남긴다.

## 이벤트 로그 필수 규칙

- 퍼널은 이벤트 존재 여부만으로 계산하지 않고 시간 순서를 검증한다.
- 세션 퍼널과 사용자 퍼널을 별도 쿼리와 별도 지표로 관리한다.
- 동일 세션의 `view → cart → purchase` 순서를 정의할 때 이벤트 시간, 상품 식별자, 세션 식별자 조건을 명시한다.
- 직접 구매, 장바구니 없는 구매, 세션 경계를 넘는 구매를 어떻게 처리했는지 문서화한다.
- 중복 이벤트 제거 기준은 실제 중복 검증 후 확정한다.
- `NULL` 브랜드·카테고리와 비정상 가격의 제외 여부 및 분모 변화를 기록한다.

## 검증 쿼리

- 원본 행 수, 고유 사용자 수, 고유 세션 수를 확인한다.
- 단계별 퍼널 수가 앞 단계보다 커지는 경우 정의와 조인 중복을 점검한다.
- 조인 전후 행 수와 키 중복을 비교한다.
- 월·일·세션 단위 집계를 섞을 때 시간대와 기준일을 명시한다.
