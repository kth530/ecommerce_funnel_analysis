# 마크다운·인사이트 작성 규칙

## 문체

- 보고체 `-다/-이다`와 명사형을 사용하고 존댓말을 섞지 않는다.
- 범위 설명은 `~` 대신 `-`를 사용한다. 원본 데이터 값은 그대로 표기한다.
- 확정적 인과 표현과 과도한 전략 용어를 피한다.
- 이모지는 고정된 역할이 있을 때만 최소한으로 사용한다.

## 헤더와 섹션

- 주요 섹션은 `## N. 제목` 형식을 사용한다.
- `###` 하위 헤더에는 불필요한 번호를 반복하지 않는다.
- 각 주요 섹션 앞에 `---` 구분선을 사용한다.
- 한 섹션은 하나의 분석 질문에 답하도록 구성한다.

## 분석 질문·가설·관찰

| 상황 | 표기 | 결과 헤더 |
|------|------|----------|
| H₀/H₁과 정식 검정 수행 | `가설 N` | `### 가설 N 판정:` |
| 분석 목적을 질문으로 설정 | `분석 질문 N` | `### 분석 질문 N 결과:` |
| 부차적 기술 비교 | 별도 박스 없음 | `### 관찰 결과` |

- `지지/부분 지지/지지되지 않음`은 정식 가설검정에만 사용한다.
- 탐색 결과를 가설 검증처럼 표현하지 않는다.
- 결과 헤더에는 핵심 방향을 한 문장으로 적되 수치보다 강한 표현을 사용하지 않는다.

## 결과와 결론

- 결과 수치는 실제 노트북 출력에서만 가져온다.
- 표에는 분모 또는 표본 수를 함께 제시한다.
- 모든 숫자를 굵게 처리하지 않고 의사결정에 필요한 수치만 강조한다.
- 각 섹션 끝에는 `> ### 섹션 결론`을 두고 핵심 결과·해석·한계를 2-4개 bullet로 정리한다.
- 최종 결론은 `핵심 발견 → 해석 → 개선 제안 → 한계 → 후속 검증` 순서로 작성한다.

## 표현 강도

| 피하기 | 권장 |
|--------|------|
| 원인이다, 견인한다 | 함께 나타난다, 관련 신호로 볼 수 있다 |
| 검증 완료, 입증 | 관찰됐다, 후속 검증이 필요하다 |
| 최우선 타깃 | 우선 검토 후보, 개선 우선순위 후보 |
| 매출이 증가한다 | 전환 개선 가능성을 검증한다 |
| 이탈 고객 | 관측 기간 내 구매 전환이 확인되지 않은 사용자 |

## 액션과 실험

- 액션은 분석 결과와 1:1로 연결하고 일반적인 마케팅 문구를 추가하지 않는다.
- 현재 데이터로 실행할 수 있는 제안과 추가 로그가 필요한 제안을 구분한다.
- A/B 테스트는 `검증 설계 예시`임을 명시하고 실제 성과처럼 표현하지 않는다.
