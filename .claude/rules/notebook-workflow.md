# 노트북 작업 규칙

## 작성 전

- 분석 단위를 이벤트·세션·사용자 중 하나로 먼저 선언한다.
- 사용할 컬럼, 분모, 관측 기간, 제외 조건을 확인한다.
- 관련 SQL이 있다면 먼저 `sql/NN_*.sql`의 이름과 역할을 정한다.
- 선행 노트북의 산출물과 실행 순서를 확인한다.

## 인트로

- 제목 다음에 `## 분석 개요`를 둔다.
- 분석 목적, 분석 대상, 핵심 지표, 데이터 한계를 간결하게 적는다.
- EDA는 데이터 구조와 후속 분석 가능성을 확인하는 역할로 작성하며 억지로 성과 목표를 붙이지 않는다.

## 셀 구성

- 한 셀에는 하나의 논리 단계만 둔다.
- 데이터 로드·집계·확인·변환·시각화를 각각 분리한다.
- 데이터 처리 셀과 시각화 셀을 합치지 않는다.
- `.head()`, `.describe()`, 검증 합계 등 중간 확인은 별도 셀의 마지막 줄에 변수명으로 출력한다.
- 대량의 `print()`와 숨겨진 상태 변경을 피한다.
- 셀 재배치·삽입·삭제 후 변수 의존성과 실행 순서를 전수 확인한다.

## SQL과 Python 역할

- ETL 이후 필터·조인·집계·분류는 SQL을 기본으로 한다.
- 분석 노트북의 인라인 SQL은 피하고 `sql/NN_*.sql`을 이름으로 호출한다.
- Python은 SQL 미지원 연산, 통계 검정, 시각화, 결과 검증에 사용한다.
- 반올림과 표시용 비율 가공은 Python에서 처리해 프로젝트 간 출력 차이를 줄인다.

## 섹션 단위

1. `## N. 제목`
2. 분석 질문 또는 가설
3. 데이터 추출·처리
4. 표 또는 시각화
5. 실제 출력에 근거한 결과
6. `> ### 섹션 결론`

정식 검정을 수행하지 않으면 가설 판정 표현을 쓰지 않고 `분석 질문` 또는 `관찰 결과`로 작성한다.

## 완료 검증

- 가능하면 커널 재시작 후 전체 실행한다.
- 마크다운 수치와 저장된 셀 출력이 일치하는지 확인한다.
- 사용자·세션·이벤트 수가 단계별로 보존되는지 검증한다.
- 퍼널 분모와 시간 순서 조건이 노트북 전체에서 동일한지 확인한다.
- 이전 노트북과 동일한 결론을 반복하지 않는다.
- 사용자 직접 수정 셀은 명시적 요청 없이 변경하지 않는다.
