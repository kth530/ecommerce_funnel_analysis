# 코스메틱 이커머스 구매 퍼널·여정 분석

공개 이벤트 로그를 이용한 포트폴리오 프로젝트다. 그로스팀의 구매 흐름 점검 요청은 **가상 업무 시나리오**다. 세션은 한 번의 방문이다. 조회 후 30일을 볼 수 있는 (고객, 상품)을 같은 분모로 두고 한 세션 기준 전환율과 세션을 이어 본 전환율을 비교한 뒤, 세션을 이어 확인한 구매를 다섯 경로로 나눠 세션을 넘은 구매 중 ‘이전 세션에 장바구니 담기 → 이후 세션에서 구매’가 가장 많은지 확인한다. 최초 cart 이후 구매 시간은 별도 집단에서 살펴보고 후속 알림 A/B 테스트를 설계한다.

## 읽는 순서

1. [01 문제 정의·가설](01_problem_hypothesis.md) — 가상 업무 상황, 분석 질문, 두 가설
2. [02 데이터 오버뷰](02_data_overview.ipynb) — 이벤트 로그의 규모·기간·컬럼·유형·기본 품질
3. [03 전처리·마트](03_mart_overview.ipynb) — 유효 세션 규칙과 분석 단위별 마트
4. [04 EDA·판단·실험 설계](04_eda.ipynb) — 가설 검증 결과, 판단, 장바구니 이탈 고객 대상 알림 실험안

**분석 흐름:** 가상 업무 시나리오 → 같은 분모에서 한 세션 기준 전환율과 세션을 이어 본 전환율 비교 → 다섯 구매 경로와 세션 묶음 → 최초 장바구니 담기 이후 구매 시간 → A/B 테스트 설계.

노트북은 SQL 본문을 복사해 보관하지 않는다. `sql`의 이름별 쿼리와 [캐시 호환 메타데이터](../sql/cache_compatibility.json)를 기준으로 `QueryCache.read_compatible_cached()`가 쿼리·마트 정의·DB 출처·파라미터·캐시 내용의 일치를 검증한다. 이전 SQL 파일이나 보관 폴더를 읽지 않는다. 정의가 다르거나 유효한 캐시가 없으면 실행을 중단한다. `ml_env` 커널, 프로젝트 `.env`, 로컬 `cache/`가 필요하다. 원본 이벤트의 전체 적재·재집계나 마트 재생성은 이 최종 분석에서 수행하지 않는다.

## 해석할 때 구분할 분모

- **1.953% / 3.036% / 6.433%:** 조회 후 30일을 볼 수 있는 (고객, 상품) 5,323,764건이 같은 분모다. 차례로 ① 한 세션 안 조회 → 장바구니 담기 → 구매, ② 한 세션 안 조회 → 구매 (담기 여부 무관), ③ 세션을 이어 30일 안에 구매. ② ÷ ③ = 47.20%로, 한 세션 기준이 잡는 구매 비중이다.
- **47.20% / 48.62% / 4.17%:** 세션을 이어 확인한 구매 342,457건(구매는 (고객, 상품)마다 처음 산 1건만 셈)을 한 세션 안 구매, 세션을 넘은 구매, 이 세션에 조회 기록 없음으로 묶은 비중.
- **68.3%:** 세션을 넘은 구매 166,513건 중 ‘이전 세션에 장바구니 담기 → 이후 세션에서 구매’의 비중. 이미 산 (고객, 상품)의 경로 구성이며, 알림 대상 미구매자의 비중과는 분모가 다르다.
- **30.361%:** 세션을 이어 확인한 구매 중 담기 단계까지 요구한 기존 퍼널 기준(①)의 비중. 세션 경계와 장바구니 담기 조건이 함께 들어 있다.
- **19.040% / 1.623% / 4.700%:** 각각 최초 cart 후 7일 관측 가능 집단, 그중 첫 24시간 미구매 집단, cart+24시간 미구매·이후 7일 관측 가능 집단을 분모로 한다. 4.700%는 자연 구매 기준선이며 알림 효과가 아니다.
